# Wenqin Zhou 个人主页设计说明

日期：2026-08-25  
状态：已确认

## 1. 目标

创建一个可部署到 GitHub Pages 的公开个人主页。首版只发布用户已经明确提供的信息，同时为未来持续添加论文、项目和奖项保留清晰的数据入口。

首版公开信息：

- 姓名：Wenqin Zhou
- 邮箱：24049200434@stu.xidian.edu.cn
- 简介：西电网信院大二
- 头像：用户提供的黑白漫画头像

## 2. 技术方案

项目使用 React、TypeScript 和 Vite。页面是无后端的单页静态站点，不使用客户端路由，以降低 GitHub Pages 部署和维护成本。

选择 React/Vite 的原因是用户明确希望采用该方案，并计划长期增加结构化内容。React 组件与 TypeScript 数据模型能够让论文、项目、奖项分别演进，同时避免把所有内容堆在一个 HTML 文件中。

Vite 使用相对资源基路径，使站点既能部署在 `<username>.github.io` 根路径，也能部署在普通仓库的项目子路径。GitHub Actions 负责构建并发布 `dist` 目录。

## 3. 信息架构

页面采用一页式学术主页结构，参考 WowPage 的信息层次，但不复制其 Jekyll 实现。

导航与内容顺序：

1. About：姓名、头像、简介与邮箱
2. Publications：论文列表
3. Projects：项目列表
4. Awards：奖项列表

首版后三个区域保留可见标题和克制的空状态文案，以表明页面会继续更新，但不生成虚构经历。导航点击后平滑滚动到对应区域；当系统开启“减少动态效果”时，取消平滑滚动和入场动画。

## 4. 视觉方向

整体定位为“学术编辑页 × 黑白漫画墨线”，延续 WowPage 清晰、可信、适合研究履历的气质，同时用用户头像建立独特识别度。

- 主色为暖白与墨黑，强调色使用低饱和暗红。
- 头像使用方形裁切、硬质细边框和轻微错位色块，不使用常见的圆形社交头像卡片。
- 姓名与大标题使用 Fraunces 字体；正文和中文使用 Noto Sans SC。字体随项目打包，避免线上字体服务不可用。
- 桌面端保留 WowPage 式双栏布局：左侧个人档案固定在视野内，右侧展示内容。
- 顶部导航保持轻量，带细线和当前区域提示，不使用大型按钮或渐变胶囊组件。
- 页面背景加入非常轻的纸张纹理和细网格，内容卡片保持扁平，避免玻璃拟态与夸张阴影。
- 首次加载使用短暂的分层淡入；交互重点放在导航下划线、邮箱链接和列表条目的细微位移。

## 5. 响应式布局

- 宽屏：最大内容宽度约 1180px，个人档案栏约 280px，正文占据剩余空间。
- 平板：缩小两栏间距，头像与文字仍保持双栏。
- 手机：改为单栏；头像、姓名和简介置顶；导航允许横向滚动；正文区块按顺序展开。
- 不制造独立滚动容器，整页只使用浏览器主滚动条，避免 WowPage 示例中内容块内滚动带来的阅读割裂。

## 6. 组件与数据边界

建议结构：

```text
src/
  components/
    Header.tsx
    ProfilePanel.tsx
    Section.tsx
    EmptyState.tsx
    PublicationList.tsx
    ProjectList.tsx
    AwardList.tsx
  data/
    profile.ts
    publications.ts
    projects.ts
    awards.ts
  styles/
    globals.css
  App.tsx
  main.tsx
public/
  avatar.jpg
```

`profile.ts` 只保存姓名、简介、邮箱和头像路径。论文、项目和奖项分别使用独立的类型化数组。各列表组件只负责渲染对应数据；数组为空时统一展示 `EmptyState`。以后添加内容时，主要修改 `src/data`，无需调整布局组件。

论文数据预留标题、作者、年份、会议或期刊、摘要、封面图及论文/代码链接。项目数据预留名称、说明、年份、图片和链接。奖项数据预留名称、颁发方、年份与说明。所有可选字段都由组件安全处理，不显示空链接或空标签。

## 7. 内容与交互

- 邮箱以 `mailto:` 链接呈现，并在视觉上直接显示完整地址。
- 头像替代文本使用“Wenqin Zhou 的头像”。
- 当前没有论文、项目或奖项时分别显示简短的“内容即将更新”提示。
- 页面不加入联系表单、访问统计、评论、登录、CMS 或数据库。
- 首版不加入用户未提供的学校英文名、研究方向、所在地、社交账号或履历。

## 8. 可访问性与质量

- 使用语义化的 `header`、`nav`、`main`、`section` 和标题层级。
- 所有文字与背景达到 WCAG AA 对比度。
- 键盘用户能访问导航和邮箱；焦点样式清晰可见。
- 支持 `prefers-reduced-motion`。
- 图片声明固定宽高，减少页面加载时的布局跳动。
- 页面标题、描述和 Open Graph 基础元数据包含姓名与学生身份，但不暴露额外个人信息。

## 9. 验证标准

实现完成后必须满足：

1. 页面准确显示姓名、邮箱、简介和指定头像。
2. 邮箱链接能够打开邮件客户端。
3. Publications、Projects、Awards 在空数据下正常显示，添加样例测试数据后能正确渲染完整条目。
4. `npm run build` 成功，产物可由静态文件服务器打开。
5. 桌面和手机宽度下无横向溢出，导航与内容可读。
6. 浏览器控制台无运行时错误。
7. GitHub Pages 工作流能够构建并发布 Vite 产物。

## 10. 非目标

本次不负责注册 GitHub 账号、创建远程仓库、绑定域名或替用户修改 GitHub Pages 设置。完成物将包含可直接推送的站点源码和部署工作流；实际发布需要用户提供或选择目标 GitHub 仓库。
